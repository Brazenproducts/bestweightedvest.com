#### 2. OSM State File Loop
- OSM processes 500 cities/run → 2 runs fills all 1000 cities in state file → stops forever
- Manual reset on Aug 28 bought 2 runs then locked up again Sep 3
- **Fixed:** Auto-reset logic added — when all cities cycled, file resets and next cycle begins automatically

#### 3. OSM Killed Supabase (Sep 4)
- OSM cron: every 10 min, `--limit=500`, each city fetched 5,000 rows for client-side dedup
- 500 cities × 5,000 rows = 2.5M rows pulled per run on nano (0.25 vCPU)
- DB reached 100% error rate, TCP CONNECT_TIMEOUT, site went down
- **Fixed:** 
  - OSM cron stopped immediately on detection
  - Removed 5,000-row-per-city dedup query entirely (DB handles dedup natively with `ignore-duplicates`)
  - Re-enabled OSM at hourly + `--limit=20` (75× less aggressive)
