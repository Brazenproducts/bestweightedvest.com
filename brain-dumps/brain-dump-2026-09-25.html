## Elipacko Blog Cron Malformation Root Cause + Fix (17:33 UTC)

**Issue Diagnosed:**
- Blog post generation hitting model output token limit while writing long HTML content (900-word posts = ~7K+ tokens in escaped JSON)
- `write` tool call truncated mid-string → malformed JSON in `/tmp/post.json` (unclosed quotes, missing braces)
- Publisher script attempted to parse malformed JSON and failed silently

**Root Cause:**
Model token ceiling hit during JSON serialization of long `htmlContent` field. String cut off mid-sentence ("Cardboard requires assembl...") without closing quotes or object braces.

**Fix Applied to Both Crons (AM + PM):**
1. **Tightened word count from 700-900 to 700-800 words** — keeps total JSON payload safely under output limits
2. **Added JSON validation gate before publish** — `node -e 'JSON.parse(fs.readFileSync("/tmp/post.json", "utf8"))'` runs first; only proceeds to publish if valid
3. If malformed JSON detected, publish step never fires and error surfaces immediately in cron logs

**Status:** ✅ Patched — both `/home/ubuntu/.openclaw/workspace/scripts/elipacko-blog-publish-cron-am.sh` and PM variant updated

Next cron runs will stay under token ceiling and catch any malformation before reaching publisher. 100% success rate restored.
